# Pyvis 全应用视觉统一 · 2026-11-18

方向：PyCharm 的紧凑编辑器层级与平台操作习惯，结合现有深色端口节点图；使用 Pyvis 自有共享主题，不以像素级复制 PyCharm 为验收目标。

## 入口盘点与实现

| 路径 | 表面及状态 | 实现 |
| --- | --- | --- |
| 应用外壳 → 项目 → 文件 | 工具栏、侧栏、目录、标签、未保存标记、状态栏 | 共用背景/正文/辅助文字/边框；工具按钮可键盘聚焦，选中与焦点明确区分；长文件名省略 |
| 编辑器 → 查找/替换 | 输入焦点、正则无效、匹配数、上一项/下一项 | 输入框和操作按钮继承公共主题，保留原快捷键及布局 |
| 编辑器 → 补全/参数/检查 | 候选选择、灰色续写、签名避让、问题提示 | 补全与诊断浮层使用共享 raised/border/selection 色；保持原 Tab/Enter/Esc 和几何定位 |
| 编辑器 → 右键/更多操作 | 操作、禁用项、平台键位提示 | Flutter popup route 负责边缘避让与键盘关闭；统一菜单字体、边框、背景 |
| 顶部更多 → 文件/记录 | 新建、保存、另存为、未保存确认、错误提示 | 对话框、按钮、输入框统一；紧凑布局新增设置入口 |
| 设置 → 字体/常规/检查/键位 | 选中导航、滚动、大字号预览、取消/确定 | 同一主题；窄宽导航收窄；关闭按钮有工具提示；高度随可用视口收缩 |
| 代码流程图 → 概览/节点 | 作用域、行号、模式、加载/语法错误/重试 | 顶栏统一；保留解析失败时的有效图 |
| 节点画布 → 图例/详情/连线右键 | 折叠图例、类型图例、容器嵌套、转接点 | 画布背景与编辑器一致；HTML 浮层边框/焦点/滚动统一；原线型、类型色、拖动、避障与画布扩展逻辑保留 |
| 运行 → 变量变化 → 容器详情 | 当前步、值变化、对象表、嵌套容器/引用 | 中性表面统一；标量类型颜色与节点端口一致；保留变化强调色 |
| 运行 → 控制台/问题 | 输入等待、输出、错误、过滤、空状态 | 继承共享控件主题与文字/边框 tokens，保留实际执行链路 |
| macOS 菜单栏 | 文件、编辑、代码、系统菜单 | 保持 AppKit 平台菜单与 Command 键位；外壳为交通灯保留位置 |
| Windows 平台分支 | Ctrl 键位、系统标题栏 | 去掉 macOS 专用交通灯留白，使用 Segoe UI；原键位分支保留 |

自定义菜单目前主要为一级弹出列表；容器详情支持多层钻取，macOS 的系统菜单由 AppKit 管理。项目未实现的三级业务菜单不宣称已验证。

## 验证记录

- Python：88 项通过；覆盖容器、分支、循环、函数、递归、异常、输入输出、多文件和检查。
- 节点模型与实际 LiteGraph：20 项通过；含类型/端口、执行连线、选中原色加粗、拖动位置与避障回归。
- 新增控件测试：工具栏 Tab/Enter 激活；500×550 逻辑视口、2× DPI、28 号字体的设置滚动与 Esc 关闭。
- 原有回归发现两处测试时序问题：Python 描述进程在 fake async 中留有 timeout；AST 结果尚未返回就查找分支标签。已让启动在真实异步区运行，并等待可见解析结果；没有删除断言或屏蔽失败。
- macOS 原生验证与最终客户端测试结果在交付前补记。
- Windows：当前环境没有执行 Windows 原生窗口验收；平台键位测试不能代替 Windows 实机视觉验收。

### 最终结果

- `flutter analyze` 无问题；客户端全量 115 项通过；随后画布挂载/主题相关 8 项重点复验通过。
- macOS Debug 构建成功。使用真实解释器路径 `/Library/Frameworks/Python.framework/Versions/3.14/bin/python3`，启动后代码检查显示“未发现问题”。构建使用符号链接 `/usr/local/bin/python3` 时曾导致 ty 环境定位失败，最终包已改用真实路径。
- 原生实际查看：编辑器与项目树、设置、查找输入焦点、macOS 文件菜单、作用域下拉、节点画布、展开的连线图例、代码块展开、变量变化、全部变量、列表详情弹窗。执行逐行运算和共享列表示例，确认实际输出与变量值。
- 画面尺寸：1400×784 逻辑窗口 / 2800×1568 截图，另检查全屏与约 1007×700 逻辑窄窗口；节点图在窗口缩放后保持绘制，长工具条可横向滚动。
- 画布曾在非当前桌面的隐藏窗口中停在“绘制中”；诊断确认 native/WebKit 尺寸有效，但 document.visibilityState 为 hidden。将窗口切至前台全屏再返回普通窗口后正常绘制。启动/重新打开现会请求移动到当前桌面；同时给 WebKit 明确初始视口并让子视图随宿主调整尺寸。临时诊断代码已移除。
- 尚未穷尽每一种嵌套容器组合和所有三级系统菜单的原生手动验收；补全、参数避让、检查、异常、递归和回放主要由现有回归覆盖。Windows 原生视觉、菜单与高 DPI 仍待 Windows 机器验收。

- `flutter analyze` 无问题；原有全量 115 项通过，新增分级菜单测试单独通过。新增测试覆盖三级菜单打开、右侧边界、跳转检查页及 Esc 关闭。
- macOS Debug 重新构建成功，实机截图核对新版主界面和字体设置窗口；Cmd+, 打开及 Esc 关闭成功。
- 原生坐标点击菜单时自动化返回 `noWindowsAvailable`，因此本轮分级菜单边界验证依据控件测试，没有声称完成原生菜单点击验收。
- 第二轮未修改 Python 执行和节点图模型；前轮运行时及节点测试结果沿用。Windows 实机验证仍未进行。
